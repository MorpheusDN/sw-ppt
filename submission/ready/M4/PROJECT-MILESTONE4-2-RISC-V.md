# RISC-V 动态记忆管理设计与测试报告

软件需求工程 2026　Milestone 4　提交整理版 0.5.1　2026 年 10 月 22 日

## 1 设计目标与实现范围

系统处理长期英文对话，在完整保留历史和来源的基础上，为每次问题判断相关记忆是否有效。已实现 JSON 导入、结构化记忆、词法和向量检索、查询时状态解析、本地神经问答、关系可视化与独立评分。原仓库 ZIP 只有 M1/M2 和过程材料，本报告对应的 src 模块为本次新增。

## 2 架构与职责

| 层次 | 模块 | 职责与输入输出 |
|---|---|---|
| 展示 | React、ECharts | 浏览和筛选记忆、选择时间与方法、查看关系、点击来源、导入导出 |
| API | server.py | 本地 HTTP、输入校验、有效导入后提交、模型配置和答案来源定位 |
| 记忆 | memory_engine.py | 原文适配、逐句保留和规则抽取、稳定 ID、候选排序、关系和有效性 |
| 模型 | local_models.py、answering.py | MiniLM 向量、统一 DistilBERT 跨窗口答案、来源轮次引用 |
| 实验 | benchmark.py、experiment.py | 预测文件与标准答案隔离、逐题日志、独立评分与汇总 |

数据流为原始对话经校验后构建 Memory；问题产生 Top-K 候选，动态方法在相同候选上解析关系，再用有效证据回答。Full Text 的回答输入为完整原始历史。全部推理在本机 CPU 执行，运行时无外部模型请求。

Memory JSON 保存人物或观察主体、属性、值、内容、会话时间、事件时间、时间依据和完整 source。无法识别的语义保留为 observation，不编造结构化属性。不同句子可指向同一轮次，ID 根据对话、轮次和句序生成。

## 3 状态解析与时间设计

关系针对本次候选集合判断，不改写持久记忆。人物或属性不同、集合型爱好和同值印证采用 RETAIN；同一收养过程后续阶段采用 UPDATE；单值属性可靠后续变化采用 SUPERSEDE。互斥值没有可靠时间顺序时输出 CONFLICT，不强选最后输入值。

查询首先剔除晚于 as_of 的事实，计划和未知时间另行标记。默认时间为语料结束时间。相对日期以会话日期为锚点；last Friday 等可解析，复杂区间、代词和第三人称仍有限制。保守拒答可能降低覆盖率，应与漏召回分别统计。

## 4 本地模型与边界

| 模块 | 实际配置 | 可复现信息 |
|---|---|---|
| 向量 | all-MiniLM-L6-v2，ONNX int8 | 384 维；均值池化、归一化；单条编码最多 128 token |
| 回答 | DistilBERT distilled SQuAD，ONNX int8 | 单段答案最长 30 token；所有方法用相同权重 |
| 长历史 | 384 token 窗口，重叠 96 token | 处理所有窗口，不做 Top-K 窗口选择；记录窗口数 |
| 环境 | Python 3.12，ONNX Runtime 1.23.2 | CPU，每会话 4 线程；依赖与模型 revision 固定 |

全文方法属于全文窗口抽取式 QA，能够使用历史末尾内容，但不具备生成模型的开放式综合能力。多跳、日期换算和多项列表可能失败。128 token 编码只影响检索表示，不删除原始 Memory；模型来源、文件哈希与上游说明在 src/models 下。

普通向量与动态向量共用同一排序、K=10 和候选 ID；前者不做状态解析。模型不读取答案、证据、事件摘要或生成摘要。推理输入文件只含问题及允许的时间、人物、属性条件。

本轮全量 Schema 校验发现 61 条句尾空白产生的空记忆，0.5.1 已修复并新增回归测试。全部向量/动态实验已重跑。全文神经推理保留 0.5.0 的原始运行，78 条预测的全文上下文哈希逐条核对与修复后完全一致，回答模型代码和原始数据亦未变；对应旧代码与证明保存在 process/archive/0.5.0-inference 和 whitespace-fix-audit.json。该修复是数据清理缺陷处理，未根据留出答案调参。

10/20 归档记录为 54/54 通过。10/22 新克隆环境复测为 49 项通过、5 项模型测试因权重未恢复跳过，两次记录分开保留。详细命令、环境、分组与逐项记录见 process/evidence/unit-tests.json 和 unit-tests.txt。

10/20 归档的 Chrome 浏览器验证包括：React 根节点、ECharts SVG、真实当前状态与历史状态、MiniLM 神经问答、全文多窗口、图节点来源跳转、空输入校验、390px 页面布局。页面无 JavaScript 异常，无外部网络请求，整页无横向溢出。证据见 ui-check.json 与真实页面截图。

导入坏数据时先构造候选 Engine，成功后才写 imported.json 并切换服务状态；原始输入文件不覆盖。API 仅监听 127.0.0.1，导入上限 20 MiB。这里的检查验证单机原型，不作互联网生产部署或高并发承诺。

已使用 jsonschema 4.26.0 按 Draft 2020-12 校验两份 Memory 导出，10207 条真实记忆与 12 条人工记忆均通过 Schema、唯一 ID 和原始来源一致性检查。测试证据和限制均与实际执行一致。

## 6 真实开发案例与界面验证

主案例为公开数据 conv-26 的 Caroline 收养过程。D2:8 研究机构，D13:1 提交申请，D19:1 通过机构面试。系统从原文自动构建阶段记忆；当前查询将前两阶段作为历史保留，最终证据为 D19:1。图中可点击任一节点回溯原始轮次。

| 输入场景 | 实际行为 | 验证证据 |
|---|---|---|
| 当前收养状态 | 返回通过机构面试的原文答案，引用 D19:1 | demo-current.json |
| 2023-06-01 历史状态 | 仅使用当时研究机构的证据，后续阶段不覆盖 | demo-history.json |
| 通用身份问题，Vector RAG | MiniLM 自动召回、DistilBERT 抽取，并显示来源轮次 | demo-vector.json |
| 相同问题，Full Text | 完整历史进入全部重叠窗口，输出来源跨度 | demo-fulltext.json |

界面显示候选记忆、事件时间和每次查询的状态，不把历史节点从存储中删除。通用问答复选框关闭实体/属性预筛选，用于包含多个人物或一般属性的问题；明确状态问题可使用常规模式。两种模式与实验设置在 README 中说明。

原人工回归集继续用于工程验证，9 题 F1=1.000、候选召回=1.000、有效召回=0.750，关系 6/6。该表只检验固定行为，真实 LoCoMo 评测另列在 M5，二者不混合。

## 7 实验衔接、复现与交付

已接入公开 10 段数据，本次项目验证使用预设 6 段：conv-26/30/41/42 为开发，conv-43/44 为留出。该选择依据上游固定顺序，与模型成绩无关；用户确认六段和划分均可由团队自行选择。原始会话共 156 个、3435 轮，自动构建 10207 条 Memory。

真实问答采用每段每类最多 2 题的哈希排序抽样，开发 30 题、留出 16 题，全部 885 道普通可评测题另存。Full Text、Vector RAG 和 Dynamic Vector 已使用相同回答模型运行，留出集三次重新推理，结果与误差见 M5。确定性推理的重复结果不构成显著性证明。

另有 12 道自建动态诊断题，依据真实轮次显式编写 10 个标准关系对，全部保存来源和理由。单次 AI 辅助标注未经独立人工复核，不冒充课程黄金标注。当前关系准确率 0.400，暴露召回和属性覆盖问题。

Windows 双击根目录 run.bat 可建立项目虚拟环境、安装锁定依赖并按固定版本下载、校验模型；已配置 Python 环境时，在 src 下执行 python server.py --data data/project-conversations.json --vector-model models/embedding --qa-model models/qa。无模型依赖的备用演示为 run-basic.bat。

交付包含源码与构建前端、模型恢复脚本及版本哈希、原始/推理/评分分离的数据、Memory JSON、54 项测试、页面证据、展示和讲稿。原会议两份、看板、M1/M2 和原模板保留；本轮工作记录不代替团队会议。成员评审、课堂展示、邮件回执须由实际活动形成。

M4 的设计、实现、测试和展示材料已形成可运行版本。六段与划分已按团队自主选择落实；动态标注需人工复核，团队编号和评分口径按实际要求填写；能力限制和当前结果不因文档定稿而省略。参考：课程项目 PDF 第 9–13 页、原 M1/M2、LoCoMo 官方仓库与随包模型来源说明。
