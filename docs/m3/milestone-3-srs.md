# 软件需求规格说明书（SRS）

**项目：** 智能体动态记忆管理 Web 应用 | **团队：** 2 / RISC-V
**课程：** Software Requirements Engineering (2026) | **版本：** 1.0 | **日期：** 2026-10-20

## 1. 目的、范围与依据

本系统面向长期对话的分析与评测使用者，将 LoCoMo 原始对话转为可追溯的结构化记忆。对每个问题，系统自动检索历史记忆，结合人物、属性和时间判断保留、更新、替代或冲突，选择有效证据后回答，并在 Web 展示全过程。本文件定义系统范围、功能、数据契约、质量要求与验收标准。

**依据：** [C]《0 - Project (2026).pdf》第 4-7、9-13 页；[P] 仓库 `docs/m2/milestone-2-vision-scope.md`。课程要求优先；本文件明确接口、默认值和验收口径，作为后续设计、实现与测试的需求基线。本 SRS 正文共 5 页。

**范围内：** 指定六段英文文本对话（四段开发、两段独立测试）；自动记忆构建与 JSON 导出；查询驱动的状态解析与回答；来源回溯；Web 可视化；Full Text、Vector RAG 与本方法的评测。技术方向沿用 Python 后端、React + ECharts；具体模型和存储实现不作为需求约束。

**范围外：** 实时聊天接入、语音、多语言、分布式和高并发部署、模型训练。图记忆、多跳、压缩、自适应检索、复杂冲突消解为扩展，不作为基础验收条件。基础冲突标记及历史证据保留仍在范围内。

**与 M2 的衔接：** Full Text 定义为完整原始对话上下文回答，TF-IDF 只能作为可选检索实现；回答 F1 与语义相似度分开。旧记忆“废弃”指在特定查询下不采用，历史证据不删除。M4 展示为 10/22 或 10/23，M3/M4 提交为 10/24，M5 提交为 11/09，取代 M2 中延至 11 月下旬的排期。

## 2. 使用者、场景与术语

| 项目 | 规定 |
| --- | --- |
| 使用者 | 分析者导入对话、检查记忆、查询与查看证据；评测者冻结配置、运行对照和导出结果。原型不要求账号系统。 |
| UC-01 构建 | 选择对话文件与数据划分，导入并抽取；查看成功数、失败项及来源；导出 Memory JSON。 |
| UC-02 查询 | 选择一个对话、输入问题与可选 as_of；查看候选、关系、有效证据、答案及原文。 |
| UC-03 历史 | 对同一实体分别问当前和过去状态；系统显示时间参照和不同适用证据，旧事实仍能回溯。 |
| UC-04 评测 | 选择冻结配置，运行三种方法，查看逐题结果、指标、失败和运行版本。 |
| Memory / 来源 | 由原文抽出的事实单元；来源是 conversation_id、session_id、turn_id 的组合，可有多个轮次。 |
| 关系 / 有效性 | 关系描述同一问题下记忆之间的联系；有效性描述记忆对指定问题和时间是否可用，不是永久全局标签。 |

**基本流程：** 对话导入 -> 记忆抽取与索引 -> 自动检索 Top-K -> 时间与关系解析 -> 有效证据 -> 回答及来源 -> Web 检查与结果导出。标准答案与标准证据仅进入评分端，不进入检索或回答输入。

## 3. 功能需求（均为基础必需）

每项需求的输入、行为和异常要求如下；对应验收编号见第 7 节。所有查询均限定于所选 conversation_id，除用户另选对话外不得混入其他对话证据。

| 编号 / 来源 | 输入、系统行为与正常输出 | 异常与验收 |
| --- | --- | --- |
| FR-01 [C9-11] 数据导入 | 接收原始对话文件与开发/测试标记；校验对话、会话和轮次 ID；输出数据清单、成功/失败计数。数据清单记录课程六段对话的实际 ID 与划分。 | 非法 JSON、重复对话 ID、缺失来源定位应拒绝并定位错误，不污染已有数据。T01 |
| FR-02 [C9,11] 记忆构建 | 从原始文本自动抽取人物、事件、时间及状态，生成符合第 4 节契约的 Memory；保留源轮次。抽取失败项独立记录，可重试。 | 无法确定事件时间时保留原表达并置空，不编造日期；成功项与失败项分开报告。T02 |
| FR-03 [C9,11] 记忆浏览 | Web 按对话显示记忆内容、时间、实体和来源；选择记忆后展示对应原始会话与轮次。 | 空记忆集显示空状态；失效来源显示定位失败，不展示其他轮次冒充证据。T03 |
| FR-04 [C10-11] 自动检索 | 接收问题、对话 ID、K 和可选 as_of；从该对话完整历史自动召回候选，输出 ID、排序、分数及检索配置。默认 K=10。 | 空问题或非法 K 拒绝；无相关候选返回空列表；不得预先注入标准证据。T04 |
| FR-05 [C9,11-13] 关系判断 | 对与问题相关的候选进行人物、属性和时间比较；输出 RETAIN、UPDATE、SUPERSEDE、CONFLICT 记录及依据，关联原文来源。 | 不同人物不得相互替代；不同属性默认并存；证据不足标记 uncertain，不能仅凭导入顺序判最新。T05-T07 |
| FR-06 [C9-12] 有效证据 | 按第 5 节的 query 与 as_of 选择 effective_ids，分别记录排除与不确定记忆及理由；保留全部历史记录。 | 时间不明或互斥证据无法消解时不强选唯一状态；历史问题不得使用查询时间之后才成立的事实。T05-T08 |
| FR-07 [C9,11] 证据回答 | 将问题、有效证据和明确标记的不确定证据交给回答组件，输出答案、来源 ID 与 answered/uncertain/no_evidence 状态。 | 无证据返回无法确定；冲突时解释分歧并引用双方；生成失败输出错误，不能伪装成功。T07-T09 |
| FR-08 [C9,11] 解析展示 | Web 同时显示问题、参照时间、候选排序、关系、有效/排除/不确定证据、答案和原文链接；关系可用图或列表辅助检查。 | 检索中、空结果和服务失败有明确状态；重复查询不串用上一次答案。T03,T09 |
| FR-09 [C9,11] JSON 导出 | 导出 UTF-8 JSON，包含 schema_version、记忆、来源和查询结果；同一构建版本的 ID 稳定，所有引用能定位。 | 导出失败显示原因；不生成无法解析或引用悬空的成功文件。T10 |
| FR-10 [C10-11] 对照评测 | 以同一 QA 集运行 Full Text、Vector RAG 和项目方法，输出三项指标、逐题预测、失败数、配置与版本。按开发/测试分开汇总。 | 评分标签与推理分离；无关系输出的对照标 N/A；失败不静默丢弃。T11 |

**可选扩展：** 图检索、多跳和复杂冲突消解不替代上述需求。关键词与向量混合检索延续 M2 方向；无论选择何种实现，均须输出可核查候选，且与 Vector RAG 对照保持检索条件一致。

## 4. 数据契约与外部接口

以下为逻辑契约；实现可采用不同路由，但不得丢失规定字段及语义。所有 ID 为非空字符串；时间采用 ISO 8601，未知时区不得擅自补 UTC。每个导出对象含 schema_version（本版为 1.0）。

| 对象 / 字段 | 类型及约束 |
| --- | --- |
| Memory 标识 | memory_id 在导出文件内唯一；conversation_id 必填；同一构建版本重复导出不得改变 ID；重建时记录 build_id。 |
| Memory 内容 | content、entity、attribute、value 为必填非空字符串；人物无法消歧时记录 uncertainty，不将同名者自动合并。抽取器可将非状态事实的 attribute 设为 event。 |
| Memory 时间 | session_time 为可空时间字符串；event_time 为可空时间字符串；time_expression 为可空原文字符串；time_status 为 known/unknown/ambiguous。时间精度保留原样，日期不得伪装成精确时刻。 |
| Memory 来源 | source 为非空数组，每项含 session_id、turn_ids（非空数组）；各来源均属于该 conversation_id，并能解析到原文。confidence 可选，若给出则在 [0,1] 内且注明计算方式。 |
| QueryRequest | conversation_id、question 必填；as_of 可空；K 为 1-100 的整数，默认 10；method 为 dynamic/vector/full_text。缺省 as_of 见第 5 节；原文内类似指令的文本仅为数据，不覆盖用户问题或系统规则。 |
| QueryResult | query_id、build_id、method、resolved_as_of、time_basis、retrieved_ids、relations、effective_ids、excluded、uncertain_ids、answer、evidence_ids、status、run_config_id。列表可空；引用属于本次构建；status 为 answered/uncertain/no_evidence/error。Full Text 可不输出 Memory 关系，须记录原文上下文范围。 |
| Relation | from_id、to_id、label、reason、source_refs；label 为四类之一。UPDATE/SUPERSEDE 的方向为旧 -> 新；RETAIN/CONFLICT 的端点按稳定 ID 排序，不表示先后。 |
| 排除 / 错误 | excluded 项含 memory_id、reason；错误含 code、message、可选 field 和 request_id，不含密钥。查询处理失败的 status 为 error，保留已完成阶段供定位。 |
| 数据清单 | conversation_id、split、原文件校验值、会话/轮次数、QA 数；必须列出课程实际六段，四段 dev、两段 test；不得以示例 ID 冒充实际 ID。 |

| 操作（HTTP 映射） | 成功响应 / 失败约定 |
| --- | --- |
| 导入 POST /datasets | 返回 dataset_id、build_id、计数与错误列表；输入不可解析为 400，字段不合法为 422，重复 ID 为 409。 |
| 浏览 GET /memories | 按 conversation_id 查询，返回记忆列表；GET /sources 使用对话/会话/轮次定位原文；不存在为 404。 |
| 查询 POST /queries | 接收 QueryRequest，返回 QueryResult；无证据是成功空结果；模型/索引不可用为 503，可重试；超时为 504。 |
| 导出 GET /exports | 返回 JSON 文件与版本；无数据返回合法空数组及版本；构建不存在为 404。 |
| 评测 POST /evaluations | 接收 split、方法集合、配置 ID；返回任务 ID。GET /evaluations/{id} 返回进度、逐题结果和汇总；失败需有原因。 |

**约束：** API 的答案和证据引用必须一致；标准答案不进入 QueryRequest。服务启动配置包括模型、检索器、超时和外部服务地址。Web 不保存或展示模型密钥；模型配置通过环境变量或本地配置注入。JSON 中字符串按 UTF-8 处理，不允许用展示页中的人工答案替代接口结果。

## 5. 时间、关系与有效性规则

**R-01 时间基准。** session_time 是说话时间，event_time 是事实发生时间；“last Friday”等相对表达以所属会话日期解释。as_of 指定查询事实有效性的时间；未指定时取所选对话中最大已知 session_time，并在 Web 展示 time_basis=conversation_end。全部会话时间未知时 resolved_as_of=null，当前状态查询须标 uncertain。仅有日期的 as_of 按该日期全天解释；时区不明且比较结果可能受影响时标记不确定。

**R-02 历史查询。** 已知 event_time 优先用于事实时间比较；缺失时 session_time 只能作为陈述时间，除非原文明确表达当时状态，不直接当作事件起点。晚于 as_of 的事件不得成为当时的有效状态；后来回忆的更早事件可作为历史证据，但须显示陈述时间和事件时间，禁止混淆。

| 关系 | 可判定条件与处理 | 验收场景示例 |
| --- | --- | --- |
| RETAIN | 对当前问题仍相关且未被推翻；新增其他属性不使旧事实失效；相同事实可去重展示但保留所有来源。 | “喜欢咖啡”之后“养猫”，查询饮品偏好仍保留咖啡；查询宠物使用养猫证据。 |
| UPDATE | 同一人物、同一过程的有证据支持的阶段演进；当前阶段用后续状态，先前阶段仍可回答历史问题。 | 申请收养 -> 通过面试；不能推断已经完成收养。 |
| SUPERSEDE | 对同一人物、同一属性和重叠适用范围，新事实明确替代旧事实，且时间顺序有证据。 | t1 住北京，t2 明确搬到上海；as_of>=t2 选上海，t1<=as_of<t2 选北京。 |
| CONFLICT | 互斥陈述在同一适用范围内同时存在，缺少足够时间或更正信息；保留双方、标不确定，不强行覆盖。 | 同一时期“仍在 A 公司”与“已不在 A 公司”，无法确定哪条有效。 |

**R-03 判定顺序。** 先限定人物、属性、问题与时间范围，再检查是否明确更正/替代，是否同一过程演进，是否存在未解决互斥，其余相关事实保留。只有可靠时序且语义支持时才确定新旧；顺序不明时不能用文件位置代替时间。无关事实不建立状态关系，也不计作有效证据。

**R-04 查询局部性。** 有效性按 (query_id, memory_id, as_of) 保存。不得永久把旧事实全局设为 inactive 后用于所有查询。“失去工作”和“开网店”可在当前业务状态问题下联系，但不能据此否认失业历史或推断重新入职。uncertain_ids 可供解释冲突，不能当作已确认 effective_ids。

## 6. 非功能需求与运行约束

| 编号 | 质量要求与验收条件 |
| --- | --- |
| NFR-01 可追溯 | 所有导出 Memory 均有有效来源；dynamic 的答案 evidence_ids 必须属于 effective_ids 或用于解释的不确定证据，不能引用被排除项；Vector RAG 引用其候选，Full Text 引用原文（若输出引用）。T02,T03,T10 |
| NFR-02 可复现 | 每次评测记录代码版本、build_id、数据校验值、模型/提示词版本、K、随机性设置、运行时间与评分配置；同一结果可由导出文件重新计算。T11 |
| NFR-03 容错 | 输入拒绝不损坏旧构建；处理失败保留原因；Web 展示错误及重试入口。外部调用默认 60 秒超时，单次查询总预算 120 秒，超限返回 error，不无限等待。T01,T09 |
| NFR-04 可用性 | 在团队记录的单机环境中，用开发集代表对话连续执行 10 次查询；至少 9 次在 120 秒内返回成功或明确业务空结果。记录硬件、网络、耗时及失败；超时错误不计成功。T12 |
| NFR-05 配置安全 | 仓库、导出和 Web 不包含真实 API 密钥；使用占位配置并给出启动说明。测试标准标签仅用于评分，不进入抽取、检索、解析、回答或调参。T11,T12 |

## 7. 验收、评测与需求追踪

以下系统验收用例覆盖正常流程、边界条件与异常处理。人工验收样例与课程独立测试集隔离。每例记录输入、预期、实际结果、版本、执行人及证据路径。

| 用例 | 输入与必须满足的预期结果 | 追踪 |
| --- | --- | --- |
| T01 导入校验 | 有效对话可导入；非法 JSON、重复 ID、缺来源分别报错；已有构建不变。 | FR01,NFR03 |
| T02 抽取与时间 | 对确定事实和含相对时间的句子抽取；核对内容及来源；时间无法解析保持 null/uncertain，不编造。 | FR02,NFR01 |
| T03 浏览与回溯 | 选择记忆或答案引用可打开正确原文；检查解析阶段和空页面；dynamic 答案不引用已排除项。 | FR03,08,NFR01 |
| T04 检索隔离 | 两个人在不同对话中有相似事实；只返回所选对话 Top-K，K 非法报错；无关问题允许空结果。 | FR04 |
| T05 保留与更新 | 咖啡/养猫按问题分别保留；申请收养后通过面试，当前取面试阶段但不回答已收养。 | FR05,06 |
| T06 替代与历史 | t1 北京、t2 上海：当前选上海，t1 与 t2 间选北京；旧证据仍可查看；不同人物不相互替代。 | FR05,06 |
| T07 冲突 | 同期互斥任职陈述且无法排序：标 CONFLICT、双方可追溯、回答 uncertain，不强选。 | FR05-07 |
| T08 时间边界 | 后来陈述的过去事件按事件时间处理；仅有未知时间时标不确定；不让未来事件污染历史状态。 | FR06 |
| T09 空证据与失败 | 无证据返回 no_evidence；模型不可用/超时返回 error；页面可重试且不展示上一次答案。 | FR07,08,NFR03 |
| T10 导出完整性 | JSON 可解析；ID 唯一、引用可定位；重复导出 ID 一致；空集导出合法。 | FR09,NFR01 |
| T11 公平评测 | 六段清单为 4 dev+2 test；三方法同 QA/回答模型；评分可重算；失败计数；标签和原文中的伪指令均不控制推理。 | FR10,NFR02,05 |
| T12 运行与配置 | 按 README 在记录环境启动；执行 10 次查询测量耗时及成功数；检查密钥配置与错误恢复。 | NFR03-05 |

**评测口径：** 优先使用课程脚本。未提供时采用以下可复现口径，并记录为团队定义；官方口径不同须版本化修订。QA F1：英文小写、去标点与冠词、合并空白后算 token 多重集 P/R 的调和平均；多参考答案取最大，双方空答案为 1，仅一方空为 0，再按题宏平均。推理失败题 F1 记 0 并单列失败数。

**证据 Recall@K：** 默认 K=10；候选按顺序取前 K 条 Memory，映射到去重的来源轮次；每题为命中标准证据轮次数/标准证据总轮次数，按题宏平均。另报有效证据召回。无标准证据题标 N/A，报告数量及有效分母；有标准证据但运行失败记 0。Full Text 若无证据定位输出则该项 N/A。

**动态准确率：** 以课程标注的关系对为单位，正确数/全部标注对数；漏召回或漏预测算错误。若课程合并 UPDATE/SUPERSEDE，则合并评分；CONFLICT 单独报告，不混入未标此类的分母；另报候选内准确率帮助诊断。官方若按有效记忆集合评分，则采用其单位并记录评分版本。对照没有关系输出时记 N/A。
