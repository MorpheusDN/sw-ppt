# RISC-V 动态记忆管理软件需求规格说明书

软件需求工程 2026　Milestone 3　版本 0.5 真实数据与本地模型　2026 年 10 月 20 日

## 1 目的与范围

本系统为长期英文对话提供结构化记忆、状态解析和证据问答，帮助使用者区分当前事实与历史事实。交付目标是可运行的单机 Web 应用、源代码、统一 Memory JSON、测试和对照实验及报告。需求依据课程项目 PDF 第 9–11 页，继承 M2 的离线文本处理范围。

使用者包括进行问答与证据检查的评测者，以及导入数据和运行实验的团队成员。系统按课程数量要求处理团队自行选择的 6 段 LoCoMo 对话，4 段用于开发，2 段仅作最终独立测试。范围不含多模态、多语言、分布式部署、在线学习和复杂图推理。关系可视化、来源跳转和基本不确定性提示属于本期范围。

## 2 关键术语与查询约束

Memory 是来源可追溯的事实或观察记录。session_time 是对话记录时间；event_time 是事实所述事件的时间。两者不得混用；相对时间以会话时间解释，无法解释时保留原词并标为未知。标识由对话、轮次和句内位置稳定生成。

有效性表示某条记忆在本次问题、人物、属性与 as_of 时间下的适用性，不是永久状态。未指定 as_of 时，以所选对话的最后已知会话时间为参照并在页面显示；不使用电脑当前时间。明确 ISO 日期可转为该日结束，其他含糊历史问题要求使用者补充时间。

| 关系 | 语义与证据要求 |
|---|---|
| RETAIN | 同值事实相互印证，或属性可并存；较早不等于无效 |
| UPDATE | 同一实体、同一过程的可靠后续阶段推进 |
| SUPERSEDE | 同一实体、同一单值属性的后续事实取代较早回答状态 |
| CONFLICT | 同一单值属性存在互斥值，且没有可靠时间顺序或解释 |

旧事实保留用于历史查询。不同人物、不同属性、集合型爱好和未实现计划不得随意互相替代。CONFLICT 为 M2 已承诺的基础处理；复杂冲突消解仍属于扩展。

## 3 业务用例

UC01 导入对话并查看记忆；UC02 查询当前状态；UC03 指定时间查询历史状态；UC04 检查原始证据和状态关系；UC05 导出记忆与查询；UC06 运行隔离的预测和评分。全部用例均应提供可理解的错误反馈，不足证据时明确拒答。

## 4 功能需求

以下 P0 为课程必做或完成闭环所需，P1 为 M2 承诺或支持可维护性的要求。编号用于实现与验收追踪，详细测试见附录。

| ID | 优先级 | 可检验的要求 |
|---|---|---|
| FR01 | P0 | 导入课程原始或规范化 JSON；校验对话、轮次和时间；错误输入不破坏现有数据 |
| FR02 | P0 | 从原文自动生成记忆，保留内容、实体或观察主体、属性、时间和完整来源；未知项不得编造 |
| FR03 | P0 | 页面按对话浏览、筛选记忆；选择记忆能看到原始会话轮次和完整文本 |
| FR04 | P0 | 根据问题从所选对话历史自动选出 Top-K 候选，输出 ID、分数和所用检索方法 |
| FR05 | P0 | 对相关事实给出 RETAIN、UPDATE 或 SUPERSEDE 与理由；无法判断时输出基础 CONFLICT |
| FR06 | P0 | 按问题实体、属性、as_of 选择有效证据；历史查询不得被较晚事实覆盖 |
| FR07 | P0 | 基于所选证据回答并关联来源；无证据或冲突、时间未知时明确不确定 |
| FR08 | P0 | 页面展示候选、关系、时间参照和有效性，支持检查至少一条完整查询链路 |
| FR09 | P0 | 导出统一 JSON，必需字段完整、ID 唯一且稳定；导出结果可被 JSON 解析器读取 |
| FR10 | P0 | 在相同条件下准备 Full Text、Vector RAG 与动态方法，输出逐题预测和三项课程指标 |
| FR11 | P0 | 开发与测试划分可审计；标准答案、证据和关系仅供评分，不进入主流程推理 |
| FR12 | P1 | 查询记录包含版本、方法、候选、关系、有效证据、答案与耗时，便于复现 |
| FR13 | P1 | 时间缺失、计划和互斥证据有独立状态；不悄悄选择输入顺序最后一条事实 |
| FR14 | P1 | 导入先校验后提交；原始数据不被覆盖；失败后旧数据仍可查询 |

FR02 的验收包含来源正确性与抽取覆盖率两个维度：来源必须逐条可定位；语义抽取在开发集人工抽样评审。当前规则与逐句保留实现不能自动获得“全量英文语义抽取已完成”的结论。FR10 的正式验收需要真实模型与团队选定数据，小样例回归不替代它。

FR04 的检索失败必须进入逐题记录。FR06 只能在已召回候选内解析，不保证弥补检索漏召回；因此分别报告候选召回与有效证据召回，定位两阶段错误。

## 5 数据和外部接口

Memory 字段约定：memory_id、conversation_id、content、entity、attribute、value、session_time、event_time、time_expression、time_basis、modality、extraction_method、source。source 保存 session、turns 数组和原始 text。事件时间可为 null；空值不等于当前时间。多条句子允许指向同一原始轮次。

查询输入为 conversation_id、question、k，可选 as_of、entity、attribute、method、open_domain。通用问答模式不从黄金标注指定人物和属性；历史问题应显式给出时间。输出 query_id、时间参照、候选列表、关系边、逐条有效性、effective_ids、answer、answer_status、evidence_ids 和上下文。查询有效性不会写回 Memory。时间均使用数据语料的本地时间，当前契约拒绝带时区偏移的混合输入。

| 接口 | 输入或输出 | 失败行为 |
|---|---|---|
| GET /api/conversations | 对话 ID、会话和轮次数 | 服务异常返回非成功状态 |
| GET /api/memories | conversation_id；对应 Memory | 未知对话返回 404 |
| POST /api/import | data；校验后的导入统计 | 无效 JSON 或重复 ID 返回 400 |
| POST /api/query | 查询对象；完整解析结果 | 空问题、非法 K 或时间返回 400 |
| GET /api/export | Memory 集合与 Schema 版本 | 输出为 UTF-8 JSON |
| GET /api/health | 健康状态、向量可用性 | 不泄露模型凭证 |

K 为 1–100 的整数；默认 10。导入大小上限 20 MiB，超出返回 413。Vector 方法使用实际本地 MiniLM 权重，缺少模型时明确不可用。Full Text 以重叠窗口覆盖完整历史，384 token 窗口、96 token 重叠；比较所有窗口后抽取一个答案，不先按相关性删减窗口。该实现为全文抽取式 QA，不等同于长上下文生成模型。

## 6 非功能需求

| ID | 要求与验收 |
|---|---|
| NFR01 可追溯 | 每条导出记忆有有效来源；自动核对原句属于相应原始轮次 |
| NFR02 可复现 | 保存数据哈希、代码版本、模型标识、K、种子和逐题输出 |
| NFR03 一致性 | 查询不修改历史；重复构建同一语料得到相同 ID；导入失败可恢复 |
| NFR04 易用性 | 页面能定位来源、显示未知和错误；窄屏无整页横向溢出 |
| NFR05 本地配置 | 默认仅监听 127.0.0.1；不在文档、导出或代码中保存密钥 |
| NFR06 可维护 | 导入、抽取、检索、解析、评分分别实现，关键边界有自动回归测试 |

语料规模、向量构建和模型调用延迟需在目标机器实测，不将人工小样例耗时作为课程长对话性能保证。上述结构性标准为团队验收要求，课程没有指定的准确率或毫秒级阈值不擅自增加为硬性指标。

## 7 验收与评测

| 验收场景 | 预期行为 | 需求 |
|---|---|---|
| 单条有来源的事实 | 答案能回到原文 | FR02 FR03 FR07 |
| 同一收养过程多阶段 | 当前返回后续阶段，前序仍可查看 | FR05 FR06 |
| 指定历史日期 | 选择当时状态，排除未来事实 | FR06 |
| 不同人物或不同属性 | 不串人物，不互相覆盖 | FR04 FR05 |
| 多项爱好 | 保留可以并存的值 | FR05 |
| 互斥事实、时间不明 | 明确不确定并保留证据 | FR07 FR13 |
| 空问题、重复轮次、坏时间 | 返回可理解的错误，旧数据可继续使用 | FR01 FR14 |
| 导出与重复构建 | JSON 可解析、字段完整、ID 稳定 | FR09 |
| 三方法正式实验 | 使用指定 4+2 划分；无标注泄漏 | FR10 FR11 |

QA F1：答案先转小写、移除英文标点和冠词、按空白分词，以 token 多重集合计算 P、R 和 F1；多参考答案取最大值。空预测与空参考同时为空时为 1，否则为 0。课程官方评分器提供后优先使用官方定义，并在报告记录差异。

Recall@K：把前 K 条候选 Memory 的 source.turns 合并去重，与黄金证据轮次集合比较。单题召回为交集大小除以黄金集合大小，再对有证据题宏平均；无标注证据题不计入分母并报告数量。有效证据召回单独统计，避免混同候选阶段。

动态状态准确率：评分单位暂定为有序的来源关系对，正确标签数除以全部黄金关系对数。未召回关系对记为错误，不能只挑系统输出的关系评分。若课程合并 UPDATE 与 SUPERSEDE，按课程规则重映射。普通基线不输出关系时标 N/A。最终以课程实际动态标注形式为准。

Full Text 输入整段原始对话；Vector RAG 从同一 Memory 集合检索后直接回答；Dynamic Vector 使用相同候选并启用解析。Hybrid 为另列方法，不能用检索器不同的结果单独证明解析模块贡献。固定回答模型、窗口策略、K、语料和评分口径，分别记录三次重新推理及均值、标准差。CPU ONNX 无随机采样，种子仅记入运行元数据，不把确定性重复解释为独立随机实验。回归样例不参与课程主表。

## 8 需求追踪与变更控制

| 需求组 | 实现位置 | 验证证据 |
|---|---|---|
| FR01 FR02 FR09 | normalize_dataset、extract、export_bundle | 数据适配、来源一致性、ID、导出测试 |
| FR03 FR08 | frontend/main.jsx 与 Web API | 浏览器当前、历史、冲突与窄屏检查 |
| FR04 FR05 FR06 FR13 | Engine.query、relation、resolve | 当前和历史、多实体、多属性、计划、冲突测试 |
| FR07 FR12 | 查询返回对象、experiment.py | 答案、来源、逐题输出和配置文件 |
| FR10 FR11 | predict、score、check_split | 标注隔离、4+2 划分门禁；真实模型实验与项目自定划分核查 |
| FR14 NFR03 | POST /api/import、只读查询 | 无效导入保留数据、查询不改写测试 |
| NFR01–NFR06 | 各模块与日志 | 54 项自动测试及浏览器记录，详见 M4 |

M3 的批准标准是需求没有未解释的关键歧义，每项必做都有验收方法，且团队完成一次真实评审。当前版本可用于评审，不能代填团队签名或推定成员已批准。详细用例、Schema、API 样例与逐项映射见独立附录；正文和附录适用同一版本。

变更应记录来源、受影响需求、接口、测试和排期，由需求负责人提交、另一成员评审。M2 已识别的变更包括：纠正截止日期；把 Full Text 与 TF-IDF 区分；细化 F1 与关系准确率；将全局 active 改为查询时有效性。整合版沿用仓库约定的 src 目录，使用 React 与 ECharts；构建资源可离线加载。原 ZIP 不含源码，这些模块属于本次新增实现。
