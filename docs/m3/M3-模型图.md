# 需求与设计模型

本文件为可编辑 Mermaid 源图。图中的角色是系统使用者，成员分工见 M1 与计划；黄金标注只进入评分，不进入推理。

## 2 查询活动

```mermaid
flowchart TD
    Q[输入对话 问题 K 可选时间] --> V{输入合法且范围明确}
    V -- 否 --> ERR[提示需要修正的字段]
    V -- 是 --> T[确定语料时间基准]
    T --> R[自动检索候选 Memory]
    R --> EMPTY{有候选}
    EMPTY -- 否 --> NONE[证据不足]
    EMPTY -- 是 --> G[按人物和属性分组]
    G --> REL[判定关系和时间有效性]
    REL --> UNC{存在影响答案的不确定性}
    UNC -- 是 --> ABSTAIN[拒答并展示冲突或未知来源]
    UNC -- 否 --> E[选择有效证据]
    E --> A[基于证据回答]
    A --> WEB[展示结果 原文和关系]
    ABSTAIN --> WEB
    NONE --> WEB
    WEB --> LOG[保存本次查询 JSON]
```

## 3 主要数据对象

```mermaid
classDiagram
    class Conversation {
      conversation_id
      sessions
    }
    class Memory {
      memory_id
      conversation_id
      content
      entity
      attribute
      value
      session_time
      event_time
      time_basis
      modality
      source
    }
    class QueryResult {
      query_id
      question
      as_of
      candidates
      relations
      decisions
      effective_ids
      answer
      evidence_ids
    }
    class Relation {
      from_id
      to_id
      label
      reason
    }
    Conversation "1" --> "many" Memory : derived from raw turns
    QueryResult "1" --> "many" Memory : candidates and evidence references
    QueryResult "1" --> "many" Relation : query scoped
```

Memory 本身不含永久 active/inactive。相同 Memory 可以在一次当前查询里是 HISTORICAL，在另一次历史查询里是 EFFECTIVE。

## 4 请求时序与评分隔离

```mermaid
sequenceDiagram
    actor U as 使用者
    participant W as Web
    participant S as JSON API
    participant E as Engine
    participant D as 原始历史和Memory
    U->>W: 输入问题和可选as_of
    W->>S: POST /api/query
    S->>E: 校验后调用query
    E->>D: 从所选对话自动检索
    D-->>E: 候选与来源
    E->>E: relation与resolve
    E-->>S: 关系 有效证据 答案
    S-->>W: JSON
    W-->>U: 原文和判断过程
    Note over S,E: 无黄金答案或证据输入
```

```mermaid
flowchart LR
    RAW[课程原始历史] --> P[预测 predict]
    QA[仅问题与允许的时间条件] --> P
    CFG[冻结模型和配置] --> P
    P --> OUT[逐题预测 JSONL]
    OUT --> SCORE[评分 score]
    GOLD[黄金答案 证据和关系] --> SCORE
    SCORE --> METRIC[指标与失败分析]
```

## 5 状态演化示例

```mermaid
stateDiagram-v2
    [*] --> researching
    researching --> applied: 可靠后续事件 UPDATE
    applied --> interviews_passed: 可靠后续事件 UPDATE
    interviews_passed --> adopted: 可靠后续事件 UPDATE
```

该图仅定义收养过程的内部单调阶段，不代表所有现实过程只能单向变化。取消或回退需要额外事件与规则；原型对无解释逆序保守标冲突。SUPERSEDE 用于居住地等单值状态，不用于把不同属性全局归并。
