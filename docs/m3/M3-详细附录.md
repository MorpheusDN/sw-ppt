# 软件需求规格详细附录

本附录与 M3 SRS 0.4 仓库整合版 配套，便于实现和评审。是否允许作为额外提交附件，按助教对总页数的说明执行。

## A 用例说明

### UC01 导入并构建记忆

参与者为维护者。前置条件是取得获准使用的原始 JSON。输入为 LoCoMo 数组或规范化 conversations 对象。系统先验证全部对话、session、turn 和时间，再按句子构建记忆，最后替换当前加载对象并保存规范化数据。成功输出导入数、Memory 数和保存位置。JSON 损坏、重复标识、缺失文本、错误时间或文件过大时拒绝整次导入，保留此前数据。默认样例文件始终不覆盖。

### UC02 查询当前状态

参与者为评测者。选择对话并输入英文问题，系统识别可确定的人物和属性，检索候选，然后在对话末尾时间参照下解析。输出答案、候选 ID 与分数、关系边、有效性和来源。若人物不唯一，要求显式选择目标；对多人物问题应分解查询。K 太小漏掉新事实时可能答旧状态，需通过召回指标发现，不能将一次成功样例视为充分证明。

### UC03 历史状态查询

输入问题与 as_of。系统以事件时间过滤未来事实，再在相关属性中比较。例：Alice 5 月住 Boston、7 月搬 Seattle；as_of 为 6 月 1 日应返回 Boston，当前查询应返回 Seattle。两次查询不改写 Memory，历史仍可反复查看。含 last year 等词但缺少明确时间时返回错误要求补充，不以电脑日期解释。

### UC04 核查证据

用户选择候选或图中记忆。页面显示完整来源文本、session、turn、会话时间、事件时间、time_basis、属性和值，以及本次决策。无法确定时间时显示未知。关系表给出前后来源和判定理由；没有关系时明确提示。前端用 React 文本节点显示对话，不将原文作为 HTML 注入；ECharts 提示采用 richText 渲染。

### UC05 导出与复现

导出 Memory JSON 和当前查询记录。检查 schema_version、ID、source.turns 与原文。Memory JSON 是标准输出，不与原始对话导入格式混用；重新运行时使用原始或规范化对话构建，不能将导出的 Memory 集合误当成 LoCoMo 原始输入。

### UC06 预测和评分

维护者准备不含答案的 questions.jsonl，并把 answers、evidence、relations 放在独立 gold.jsonl。predict 仅接收原始对话、问题、时间条件和查询配置；score 读取预测与 gold，拒绝问题 ID 缺失或重复。课程主运行必须声明真实 4+2 清单、同一回答模型和向量模型。原始测试历史允许构建 Memory；黄金摘要、observation、event_summary 和标准证据不参与抽取与检索。

## B 状态解析规则

令查询 q=(conversation, entity, attribute, as_of)，候选集合 C=Retrieve(q, H, K)。有效集合 E=Resolve(q,C)，不是对 H 的破坏性更新。实体或属性不能确定时保留多个观察或返回不确定，不推测全局互斥性。

1. 计划和愿望只作计划记录，不作为已发生的当前事实。
2. 可靠 event_time 大于 as_of 的候选标 FUTURE，不作为历史时点证据。
3. 时间不明标 UNCERTAIN_TIME。无可靠顺序的互斥单值事实标 CONFLICT。
4. 同一属性的重复值 RETAIN；集合型属性如爱好保留各值。原始逐字观察也不做单值覆盖。
5. 收养过程的阶段序关系为 researching < applied < interviews_passed < adopted。已知后续阶段标 UPDATE，逆序阶段未经解释时标 CONFLICT。
6. 居住地等单值属性有可靠前后顺序时标 SUPERSEDE。较早状态只在本次当前问题中标 HISTORICAL。
7. 较晚“开店”不能覆盖“在 DoorDash 工作”的独立属性。需要查询职业综合状态时应设计明确的投影层；当前原型不声称已实现该语义综合。
8. 只要候选中包含影响答案的冲突、计划或时间未知，原型采取保守拒答。它可能因无关候选拒答过多，应在开发集评审改进；不能隐藏这一失败模式。

查询“截至某日期实际发生了什么”使用完整历史中的事件时间，可能含后来追述的信息；它不同于“某日期当时已知什么”。后者还需限制 session_time，属于待扩展功能，不能混为同一种历史查询。

## C 数据字典

| 字段 | 类型 | 约束 |
|---|---|---|
| memory_id | string | 对话、轮次、句内序号的 SHA-256 前缀；同一输入稳定 |
| conversation_id | string | 语料的对话标识，不使用测试答案生成 |
| content | string | 原始轮次中的完整句子 |
| entity | string | 显式第一人称事实的说话人；逐字观察时仅表示观察主体 |
| attribute | string | adoption_status、residence、employment:公司、hobby 或 observation |
| value | string | 规则解析的状态或原始内容；不虚构缺失值 |
| session_time | string/null | ISO 本地会话时间 |
| event_time | string/null | 解析到的事件时间；无时间表达式时可采用 utterance 基准 |
| time_expression | string/null | 原始相对词或“未解析时间表达式”标记 |
| time_basis | enum | event、utterance、unknown |
| modality | enum | assertion、plan |
| extraction_method | enum | rules-v1、verbatim-fallback |
| source.session | integer/string | 对应导入 session_id |
| source.turns | string[] | 当前按句切分通常单轮；格式允许多轮 |
| source.text | string | 未修改的原始轮次文本 |

关系边和 decisions 只在查询对象中保存。若句内序号因分句策略变化而改变，必须升级 extraction_method/engine_version 并重新生成，不把新 ID 冒认为旧版本。

### 规范化对话输入

```json
{"conversations":[{"conversation_id":"example","sessions":[{"session_id":1,"timestamp":"2023-05-01T10:00:00","turns":[{"turn_id":"D1:1","speaker":"Alice","text":"I live in Boston."}]}]}]}
```

### 查询输入

```json
{"conversation_id":"synthetic-adoption","question":"Where does Alice live?","k":10,"as_of":"2023-06-01T23:59:59","method":"dynamic_lexical"}
```

正常结果应包含 answer=Boston、time_reference=explicit、一条有效 Memory 与对晚于 6 月 1 日地点记忆的 FUTURE 判定。完整输出样例见 `src/results/synthetic-predictions.jsonl`，包含实际运行生成的 ID。

### 错误输出

```json
{"error":"question must be non-empty"}
```

GET 未知路径返回 404；POST /api/query 对未知字段、非法 K、歧义人物、无效时间等返回 400；通用问答 open_domain=true 时不做人物属性预筛选，时间请显式输入；跨来源的浏览器 POST 返回 403；过大请求返回 413。输入校验不能替代正式鉴权，服务仅适用于本地课堂原型。
