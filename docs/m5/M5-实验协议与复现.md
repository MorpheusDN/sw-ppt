# 实验协议、复现与课程替换

本版已有真实本地模型实验，数据划分为项目预设，动态标注为自建诊断。模型和结果文件齐全，不需要 API 密钥。

## 已执行的实验

- 固定上游 locomo10.json，前六段为项目验证，前四段开发，后两段留出；其余四段未作本轮主表。
- 每段对 category 1–4 各按 SHA-256(question) 排序取前 2 题。开发 30、留出 16；全部 885 道普通可评测题保存在 questions.all-* 与 gold.all-*。category 5 对抗题缺少普通答案，单独协议尚未实施，未当作空答案计分。
- MiniLM ONNX int8 为向量，DistilBERT SQuAD ONNX int8 为共同回答器；不训练或微调。K=10；动态解析不改变候选 ID。
- Full Text 使用完整原始历史，384 token 窗口、96 token 重叠，遍历所有窗口。它是全文抽取式 QA，不是长上下文生成式 LLM。
- 开发集一遍，留出集分别以种子 17/23/41 重新运行三种方法。模型无随机采样，结果可能完全相同；不能把零标准差解释为统计显著或普遍稳定。
- 12 道自建真实轮次动态题单独诊断；10 个有序关系对。标注为单次 AI 辅助编写，未独立人工复核。多项题采用短答案片段诊断，完整多项答案质量不由此衡量。

## 安装与命令

推荐 Python 3.12。根目录 run.bat 创建 src/.venv 并安装 requirements-models.txt；模型权重已经提供，推理不再下载模型。不需要修改前端时无需 Node.js。

在 src 下依次运行：

```powershell
python -m pip install -r requirements-models.txt
python prepare_data.py
python prepare_dynamic.py
python -m unittest discover -s tests -v
python run_benchmarks.py
python benchmark.py predict --questions data/eval/questions.dynamic.jsonl --method dynamic_vector --out results/real/dynamic_vector-diagnostic.jsonl
python experiment.py score --predictions results/real/dynamic_vector-diagnostic.jsonl --gold data/eval/gold.dynamic.jsonl --out results/real/dynamic-diagnostic-metrics.json
python summarize_results.py
```

run_benchmarks.py 默认开发一遍、留出三遍，全文处理可能需要十几分钟或更久，依机器而变。没有复制单次预测冒充重复运行。summarize_results.py 在任何预期文件未完成时拒绝汇总，逐题核对普通向量和动态向量的候选 ID 完全一致。

扩大到全部题目时，将 benchmark.py 的 --questions 指向 questions.all-dev.jsonl 或 questions.all-test.jsonl，并用对应 gold.all-* 独立评分。当前主表只代表抽样 46 题，不把未运行的 885 题写成已完成。

## 数据隔离与口径

project-conversations.json 仅包含 sample_id 与原始 conversation。questions.*.jsonl 仅允许问题 ID、对话 ID、问题、可选时间/实体/属性；gold.* 只传给评分器。benchmark.py 的预测命令没有 gold 参数。原始 QA、观察、摘要不用于记忆构建。

F1 采用随包 metrics.py 的英文 token 多重集合规范化，非语义相似度。证据召回将 Top-K Memory 映射到原始轮次并去重，题级宏平均；无证据标注不计分母。动态准确率按黄金有序轮次对微平均，漏召回关系计错，多句造成同一对标签歧义计错。Full Text 检索召回为 N/A，普通问答没有动态标签时动态准确率为 N/A。

模型编码最多 128 token 不删除原始 Memory；QA 处理全部窗口，答案最多一个 30-token 片段。Full Text 的跨窗口概率比较、单跨度输出和多跳能力限制均适用于本轮配置。延迟包含单题推理；首次向量缓存构建也计入首题，环境冷热与并行任务会影响时间，不能当作生产性能保证。

## 团队调整与标注复核后的复现

1. 六段与 4＋2 由团队自行选择，当前记录在 project-split.json。用户已确认这一权限，无需等待课程指定；如团队今后修改选择，应另存划分、记录理由，再重新运行全部方法。
2. 原始 QA 与证据来自 LoCoMo；动态关系和最终有效证据的自建标签应由另一成员依据原文独立复核，记录争议与修订，再按评分契约运行。不将模型自己的输出自动当作标准答案。
3. 如改变划分或方法，使用开发集确定参数，再冻结代码和模型。在允许使用的原始测试对话上自动构建记忆和预测，测试答案不参与调参。
4. 按课程评分器重新评测并更新汇总、M5 报告与展示；如课程要求生成式 LLM，替换统一回答器并对三方法全部重跑，不能拼接旧模型数字。

当前阶段已经查看过一些留出原文并构建示例，因此这轮叫项目留出验证，不叫严格盲测。已有真实结果可以用于展示工程实现和分析边界，最终报告应以团队实际采用且完整记录的设置和复核标签为准。
